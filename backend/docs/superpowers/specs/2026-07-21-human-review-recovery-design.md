# 人工复核与运行恢复设计

## 目标

修复周报截止位并列在输入确认页提交错误类型的问题，并让日报、周报按各自状态独立推进。人工决策必须说明触发原因、影响范围和恢复动作；技术追踪字段不占据主界面。

## 决策分流

- 输入确认页只处理影响共享事实的决策，例如 OCR 结果确认。
- 周报专属决策统一在报表预览页的“周报复核”处理。
- 周报待确认或未到发布日不得阻断日报预览、发布。
- Top-3 并列必须先选择，再显式确认；接口答案始终为项目数组。

## 状态语义

- `needs_review`：存在待人工确认项目。
- `not_due`：日历和页面根据发布窗口校验派生的展示状态；持久化目标保持 `needs_review`，不扩展既有状态契约。
- `failed`：解析、计算或发布发生真正错误，或存在业务硬阻断。
- 决策提交后立即重新计算对应目标的校验摘要，避免待确认数量滞后。

## 恢复路径

- 输入正确但执行中断：重试当前 Run，保留四类输入并增加尝试次数。
- 输入错误、输入已冻结或已发布后修正：创建同日修订 Run，重新上传输入；旧 Run 保持只读。
- 下一工作日：从日历创建新日期 Run，并引用最近已发布日报作为基线。

## 页面要求

- Top-3 复核说明候选项处于相同截止位，选择只影响周报前三展示，不修改日报或人员事实。
- 内部决策编码和事实引用折叠到“技术追踪信息”。
- 输入冻结和运行失败状态提供清楚的同日修订入口。

## 验收

1. 周报决策不会出现在输入确认页，也不会阻断日报预览。
2. Top-3 确认请求发送数组，错误提示使用中文。
3. 周中目标不再记为 `failed`，页面稳定显示“未到周报日”。
4. 决策提交后目标摘要中的待确认数量立即更新。
5. 冻结输入可从当前页面创建同日修订 Run。
