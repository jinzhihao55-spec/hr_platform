## 4. 输入文件与追溯

每个运行都显示四项输入完整，并记录以下审计元数据：

- 来源类别和原始扩展名。
- 结构化行数和解析状态。
- Schema 版本、解析器版本和 SHA-256 指纹。
- 报告日期、运行编号、规则版本和关联日报基线。
- 输入确认后的冻结状态。

原始上传文件在解析后从临时目录删除。系统当前不保存或展示客户端原始文件名，以减少文件名携带人员信息的风险；文件级追溯使用运行编号和 SHA-256 指纹。若验收制度要求保留原始文件名，应另行设计脱敏文件名字段和保存期限，不能直接长期保存客户端文件名。

## 5. OCR 使用边界

本次隔离 Docker 栈没有注入 Qwen 密钥：

- 人员表、离职人员报表通过前端上传真实 Excel。
- OA/Release、招聘截图使用导师已复核的结构化 Excel 转录，通过对应正式槽位上传。
- 本次验证证明四槽位、计算、发布、导出和历史链路，不作为新的 Qwen OCR 证据。
- 07-08 至 07-15 已有单独验收记录证明 `qwen3.7-plus` 能从正式图片入口调用；模型只负责结构化识别，不参与数值计算。

## 6. 本轮发现并修复的问题

1. 日报发布后周报预览未刷新，导致 07-10 周报按钮仍不可用。现已在日报发布成功后重新读取周报预览。
2. 已发布日报在日历顶部仍显示“可预览”，周中周报显示“失败”。现已分别显示“已发布”和“未到周报日”。
3. 日报桌面页被宽表最小内容宽度撑出页面。现已限制 Grid 轨道收缩，宽表只在自身容器滚动。
4. 周中运行记录把 `weekly_last_workday_only` 当作日报阻断。现仅将其解释为周报未到期，其他真实阻断不受影响。

以上问题均先增加失败回归测试，再修改实现；修复后已在重建的 Docker 页面中复现验证。
