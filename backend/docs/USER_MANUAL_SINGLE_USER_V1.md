# 人事报表智能体单用户版用户手册

版本：V1
适用对象：人事报表操作人员、业务验收人员
适用范围：日报、周报；月报尚未纳入本版本

## 1. 系统能做什么

系统以 Web 页面作为正式入口，接收指定报告日的四类输入，完成解析、人工确认、确定性计算、校验、预览、发布和 Excel 下载。每次运行都保留规则版本、输入指纹、计算日志和不可变发布版本。

视觉模型仅用于图片转结构化数据。当前配置模型为 `qwen3.7-plus`。日报和周报的数值由 Python 规则计算，模型不直接决定报表数值。

## 2. 使用边界和数据安全

- 当前是单用户本地版本，只能通过部署机器上的 `http://127.0.0.1:8080/` 访问。
- 不得把服务直接暴露到局域网或互联网；本版本没有企业 SSO 和多用户权限隔离。
- 人员表、离职人员报表必须使用 Excel。协议签署/OA Release 优先使用固定九列 Excel，图片仅作为过渡或备用输入；招聘数据可使用 Excel 或图片。
- 真实图片只有在公司批准对应云端模型及数据路径后才可上传。不能批准云端 OCR 时，请改传 Excel。
- 图片识别结果必须由操作人员确认；无法辨认的字段不得猜测。
- 原始上传文件在解析完成后删除。已发布报表、计算快照和审计元数据按正式记录保留。
- 密钥只保存在部署环境的 `deploy/.env`，不得写入代码、截图、操作手册或聊天记录。

## 3. 正式输入要求

每个报告日必须分别上传四类来源。系统不会根据文件名自动猜测类别。

| 页面槽位 | 可用格式 | 关键内容 | 操作要求 |
|---|---|---|---|
| 人员表 | `.xlsx`、`.xls` | 工号、员工类型、状态、入职/离职日期、事业部、项目 | 上传当日报告口径下的完整人员表 |
| 离职人员报表 | `.xlsx`、`.xls` | 流程单号、流程状态、离职方式、申请时间、LWD | 使用正式离职人员报表，不需要额外的“离职明细” |
| 协议签署 / OA Release | 优先 Excel；也支持常见图片 | 固定九列 Excel：单号、申请时间、创建人、被申请人姓名、职位、项目名称、入职时间、最后工作日、在岗时长 | 固定九列直接解析；图片会调用 OCR，识别后必须确认并补齐缺失 LWD |
| 招聘数据 | Excel 或常见图片 | 招聘专员、动态月份列、预计入职、合计 | 图片会调用 OCR，识别后必须确认 |

建议在上传前确认：

1. 报告日期正确，四个文件来自同一业务截点。
2. Excel 不是空表，表头和日期列未被手工改名。
3. 图片完整包含表头、合计行和关键日期列，文字清晰、无大面积遮挡。
4. 文件中没有与本次报告无关的临时批注或隐藏测试值。

## 4. 首次使用：建立初始基线

系统必须从一份 HR 已验收日报开始滚动计算。首次使用按以下顺序操作：

1. 打开“运行日历”，选择首个基线日期并创建运行。
2. 在四个固定槽位上传该日期的人员表、离职人员报表、OA/Release 和招聘数据。
3. 如使用图片，等待识别完成。数据量较大或远端 OCR 较慢时可能需要约一分钟。
4. 在“人工确认”区逐项核对识别结果，选择“确认”或替换输入。
5. 四项输入和全部人工确认完成后，“建立初始基线”区域可用。
6. 上传同一日期的 HR 已验收日报，点击“上传本日定稿”。
7. 系统校验 `Sheet1`、日期列、合并单元格和“在岗时长”，将该文件登记为不可变初始版本。
8. 返回运行日历，从下一工作日开始正常滚动处理。

初始基线只做一次。不得用未验收文件建立基线，也不要通过修改系统预期值绕过校验。

## 5. 日报操作流程

### 5.1 创建运行

1. 打开“运行日历”。
2. 切换到目标月份，点击目标工作日。
3. 当日不存在运行时，按页面提示创建；已有运行时直接进入。

### 5.2 上传四类输入

1. 在“人员表”槽位上传人员 Excel。
2. 在“离职人员报表”槽位上传离职 Excel。
3. 在“协议签署 / OA Release”槽位上传 Excel 或图片。
4. 在“招聘数据”槽位上传 Excel 或图片。
5. 等待每个槽位显示“解析完成”或“识别已确认”。

上传必须从正确槽位发起。若系统提示结构不匹配，应检查文件类别和表头，不要把同一文件尝试塞入其他空槽位。

每项输入会记录来源类别、文件扩展名、解析状态、结构化行数、解析器版本和 SHA-256 指纹，并与报告日期、运行编号和规则版本关联。系统不保存或回显客户端原始文件名，避免文件名中可能存在的人员信息进入长期审计记录；需要追溯时以运行编号和输入指纹为准。

### 5.3 人工确认

- Excel 解析无疑问时，页面通常显示“无需确认”。
- 图片识别后会出现确认问题。核对表头、日期、合计和行数，再点击“确认”。
- OA/Release 图片路径不直接采信视觉模型返回的 LWD。系统先按单号读取已发布日报历史；历史仍无日期时，必须在对应行输入 LWD。系统根据报告月份自动判断是否计入 Row30。
- 识别结果不完整或日期列错误时，选择替换输入并上传更清晰图片或 Excel。
- 所有问题回答后，系统冻结本次输入并生成输入指纹。需要更换文件时，应从日历为该日期创建新运行。

### 5.4 预览和校验

点击“继续预览”，在日报预览中检查：

- Row2 至 Row40 的事项、本次值、上一发布基线和差异。
- 阻断数和复核数均为 0。
- 今日入职、今日离职、MTD、YTD、预估入职和预估离职符合业务预期。
- “在岗时长”合计与日报 Row14 一致。

校验未通过时不能发布。先返回输入页查看人工确认和错误提示；不要直接修改导出的 Excel。

### 5.5 发布和下载

1. 点击“发布日报”。
2. 发布成功后按钮显示“日报已发布”，运行状态显示对应发布结果。
3. 打开左侧“日报”，选择报告日期。
4. 点击“下载日报”取得正式 Excel。
5. 可点击“计算日志”查看每一行的输入源、公式、最终值和校验结果。

发布后的快照不可修改。同一日期需要修订时，应创建新运行并发布新版本，旧版本仍保留在“历史归档”。

## 6. 周报操作流程

- 系统可在每日预览中展示周报过程结果，但周报只允许在本周最后一个工作日发布。
- 最后一个工作日完成当日日报输入和确认后，切换到“周报”预览。
- 当日日报发布后，页面会自动刷新周报预览；无需退出页面或重新创建运行。
- 核对主体与事业部在职拆分、正式/实习/劳务分类、本周入离职、成本中心与项目汇总。
- 确认所有阻断校验通过后点击“发布周报”。
- 打开左侧“周报”下载正式 Excel，或查看周报计算日志。

非周末工作日显示“未到周报日”属于正常状态，不代表计算失败。

## 7. 页面说明

| 页面 | 用途 |
|---|---|
| 运行日历 | 按日期创建或进入运行，查看日报/周报状态 |
| 运行工作台 | 上传四类输入、确认 OCR、查看输入指纹和规则版本 |
| 报表预览 | 比较基线和本次结果，独立发布日报或周报 |
| 日报 / 周报 | 查看已发布版本、下载 Excel、进入计算日志 |
| 计算日志 | 查看逐行取数、公式、最终值和校验清单 |
| 系统状态 | 检查 MySQL、Redis、数据库迁移、产物目录和生产配置 |
| 历史归档 | 查看不可变发布版本并重新下载产物 |
| 设置 | 只读查看当前员工类型和流程状态口径；业务口径变更需走配置评审 |

## 8. 常见状态和处理方法

| 页面状态 | 含义 | 处理 |
|---|---|---|
| 待录入 | 四类输入未齐 | 按固定槽位补齐 |
| 录入中 | 文件正在解析或 OCR | 等待完成，不要重复点击 |
| 待确认 | 存在 OCR 或业务澄清 | 核对后回答，错误时替换输入 |
| 可预览 | 输入和校验已就绪 | 进入预览 |
| 日报已发布 / 日报周报已发布 | 正式版本已生成 | 到报表页下载 |
| 未到周报日 | 当前日不是本周最后工作日 | 继续日报流程，周末再发布周报 |
| 处理失败 | 解析、计算或发布中断 | 阅读错误信息，检查系统状态后点击重试 |

常见问题：

- 图片上传失败：检查视觉模型配置，或改传 Excel。
- 图片长时间处理中：远端 OCR 允许最长约 180 秒，避免连续重复上传。
- “缺少上一份已发布日报基线”：先建立首日基线，或确认上一工作日日报已发布。
- 周报发布按钮不可用：确认目标日是本周最后一个工作日且校验通过。
- 下载文件与预览不一致：停止使用该文件，保留运行编号并执行验收手册中的制品比对。
- 页面显示系统未就绪：打开“系统状态”，由维护人员检查容器、数据库迁移和生产配置。

## 9. 结束前检查

每日完成后确认：

1. 当日运行状态已发布。
2. 下载的日报可正常打开，日期列和历史列完整。
3. 计算日志中没有阻断失败。
4. 周末工作日已额外发布并下载周报。
5. 修订通过新版本完成，没有覆盖旧文件。

## 10. 当前限制

- V1 只支持单用户本地部署。
- 月报流程和页面尚未交付。
- OA/Release 与招聘图片识别仍需人工确认。
- 移动端可用于查看和轻量操作；大表核对与正式发布建议使用桌面浏览器。
- 真实数据验收只在导师或授权 HR 的本机隔离环境进行，不进入 Git 和学生共享目录。
