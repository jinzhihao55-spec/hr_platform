## 0. 多源输入（Excel 非必须）

用户可上传 **Excel、截图、或混合**；四类表数据齐全即可进入 Agent 2。

| 源 | 格式 | ① 人员 | ② 离职 | ③ OA | ④ 招聘 |
|----|------|--------|--------|------|--------|
| Excel | xlsx/xls | ✅ | ✅ | ✅ | ✅ |
| 截图 | png/jpg | ✅ Prompt 4 | ✅ Prompt 4 | ✅ Prompt 4 | ✅ Prompt 4 |
| 混合 | 上两者 | ✅ 可交叉核对 | ✅ 可交叉核对 | ✅ 可交叉核对 | ✅ 可交叉核对 |

**四类均可仅截图**（无 Excel），但 ①② 截图须满足 §0.1 确认规则方可 `ready_for_calc=true`。

**模式 A**：对话附件；**模式 B**：门户上传 → 先入 raw 层（[`data_contract.md`](../data_contract.md) §1）。

### 解析流程（Agent 1）

```
上传 → pandas 读 Excel（若有）
     → Prompt 4 OCR 读截图（若有）
     → 合并 / 冲突标记（Q6）
     → StagingPayload → 写入 staging 库
     → ready_for_calc=true → 触发 Agent 2（须过 §0.1）
```

### 0.1 截图 OCR 确认规则（四类通用，①② 更严）

| 表 | OCR 关键列（★ 缺则 blocking） | 仅截图时 ready_for_calc |
|----|------------------------------|-------------------------|
| ① 人员 | 员工类型★、工号★、入职日期★、离职日期★、事业部★ | `confidence=high` **且** 用户确认 **或** 补 Excel |
| ② 离职 | 流程单号★、离职方式★、申请时间★、LWD★ | 同上 |
| ③ OA | 单号★、申请时间★、当前状态★ | `confidence≥medium` + 用户确认；`low/failed` → 阻断 |
| ④ 招聘 | 合计行★、动态月份列★ | 同③；Q7 合计冲突另阻断 |

| confidence | 处理 |
|------------|------|
| **high** | ①②：仍须 **Prompt 5 ocr_review** 请用户点确认（默认 blocking）；③④ 可直接进 staging |
| **medium** | 全部 → **Prompt 5**，展示 OCR 预览，用户确认后 `ready_for_calc=true` |
| **low / failed** | **Prompt 5**，要求重拍 / 补 Excel；**不得** silent 进 Agent 2 |

①② 截图-only：**禁止**在未确认时自动发布；门户应提示「人员/离职建议 Excel，截图需人工确认」。

### Q6 · 多源冲突

| 情况 | 处理 |
|------|------|
| 仅 Excel | 直接采用，`source=excel` |
| 仅 OCR（四类均可） | 采用 OCR；见 §0.1 确认规则 |
| Excel + OCR 同字段不一致 | **Excel 优先**；差异写入 `merge_conflicts[]` 与计算日志 |
| 关键字段 OCR 看不清 | `null` + Prompt 5，**不得猜** |

`missing` / `parse_errors` / `ready_for_calc=false` → Prompt 5，**不进 Agent 2**。
