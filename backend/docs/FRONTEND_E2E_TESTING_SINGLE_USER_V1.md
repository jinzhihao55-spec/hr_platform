# 人事报表智能体前端验收与测试手册

版本：V1
适用对象：QA、学生开发组、导师验收人员、部署维护人员

## 1. 验收目标

验收必须从 Web 页面完成用户真实链路，不能只调用 API。API、单元测试和数据库检查用于定位与补充证据，不能替代前端操作。

核心结论需要同时回答：

1. 操作人员能否通过页面完成四项上传、OCR 确认、预览、发布和下载。
2. 日报和周报是否与 HR 已验收文件一致。
3. 错误、阻断、重试、历史版本和系统状态是否可理解、可恢复。
4. 桌面和手机视口是否无页面级溢出，键盘焦点是否可见。
5. 测试过程是否没有把真实输入、业务值、截图或密钥写入仓库。

## 2. 测试分层

| 层级 | 数据 | 目的 | 是否可由学生执行 |
|---|---|---|---|
| 单元/集成测试 | 仓库内假数据 | 规则、状态机、API 契约和组件行为 | 可以 |
| 假数据发布回归 | 可公开假数据及标准答案 | 预览、发布、Excel 回读、样式和 manifest | 可以 |
| 浏览器端到端测试 | 假数据；导师本机可使用真实材料 | 验证用户实际操作链路 | 学生仅使用假数据 |
| 导师本机 Golden 回放 | 真实输入和 HR 已验收报表 | 最终准确性验收 | 仅导师或授权 HR |

真实字段值、真实汇总值、结构化 OCR 中间表、截图和下载报表不得进入 Git、学生共享目录或测试断言。

## 3. 环境准备

### 3.1 启动本地单用户栈

在后端仓库执行：

```bash
cp deploy/.env.example deploy/.env
# 填写 deploy/.env 的独立强随机密钥及经批准的视觉模型配置
docker compose --env-file deploy/.env -f deploy/compose.yaml config --quiet
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
python scripts/check_ready.py
```

浏览器访问 `http://127.0.0.1:8080/`。验收前“系统状态”必须全部就绪。

### 3.2 测试数据

- 学生测试：使用假人员、假工号、假流程号和已知标准答案。
- 导师测试：输入根目录必须在仓库外，按日期隔离；测试结束清理临时下载和截图。
- 首日准备四类输入和同日 HR 已验收日报；后续每日准备四类输入和当日验收日报。
- 周末工作日额外准备 HR 已验收周报。

## 4. 仓库自动化门禁

后端：

```bash
PYTHONPATH="$PWD" python -m pytest -q
PYTHONPATH="$PWD" python scripts/run_single_user_regression.py --mode fake
python scripts/scan_sensitive_artifacts.py .
```

前端：

```bash
npm test -- --run
npm run lint
npm run build
```

数据库仓库：

```bash
bash tests/test_migrations.sh
```

三个仓库同级时，正式发布还应设置 `FRONTEND_CONTEXT` 和 `DATABASE_CONTEXT`，运行后端 `tests/test_deploy_contract.py`。

## 5. 浏览器端到端用例

建议桌面视口使用 1440 x 900，移动视口使用 390 x 844。每个用例记录日期、运行编号、浏览器、结果和缺陷编号，不记录业务值。

### UI-001 启动与系统就绪

1. 打开首页，确认自动进入“运行日历”。
2. 打开“系统状态”，点击“重新检查”。
3. 确认 MySQL、Redis、数据库结构、产物目录和生产配置全部就绪。
4. 浏览器控制台不得出现未处理错误。

预期：页面可访问，只有 Web 端口对本机开放，系统状态为就绪。

### UI-002 初始基线

1. 从日历创建首日运行。
2. 通过四个固定槽位分别上传四类输入。
3. 完成图片识别确认。
4. 上传同日已验收日报并建立初始基线。
5. 返回日历创建下一工作日运行。

预期：四项输入不会被错误分配；初始日报登记为不可变版本；下一日自动关联基线。

### UI-003 常规日报

1. 从日历进入报告日。
2. 上传人员表和离职人员报表 Excel。
3. 上传 OA/Release 和招聘 Excel 或图片。
4. 逐项确认 OCR。
5. 点击“继续预览”，核对 Row2 至 Row40、基线、本次和差异。
6. 发布日报，在日报页下载 Excel。

预期：运行状态依次变为待录入、待确认、可预览、日报已发布；下载文件可打开。

### UI-004 真实 Qwen OCR

仅在授权环境执行：

1. 确认 `LLM_VISION_MODEL=qwen3.7-plus` 且密钥未写入前端 bundle。
2. 通过页面上传一张 OA/Release 图片和一张招聘图片。
3. 等待远端调用结束，检查页面出现人工确认问题。
4. 确认识别预览与原图一致后提交。

预期：后端日志能证明发生真实远端 OCR 调用；模型只返回结构化识别结果；未确认前不能进入发布。

### UI-005 预览、发布、下载一致性

1. 在日报预览确认阻断 0、复核 0。
2. 发布日报并下载。
3. 打开历史归档，再次下载同一版本。
4. 比较两次下载的哈希和工作簿结构。

预期：同一发布版本不可变；预览快照、首次下载和归档下载对应同一版本。

### UI-006 周报

1. 在非周末工作日打开周报预览。
2. 确认页面提示“未到周报日”或说明当前只可过程预览。
3. 在本周最后一个工作日完成当日日报后打开周报预览。
4. 核对事业部、主体、员工类型、入离职和成本中心项目汇总。
5. 发布并下载周报。

预期：非周末工作日不能发布；最后工作日校验通过后可发布；日报发布不受非到期周报影响。

### UI-007 计算日志与历史版本

1. 从日报或周报页点击“计算日志”。
2. 展开若干行，检查输入源、公式、最终值和校验。
3. 切换不同日期或周次。
4. 打开历史归档，检查日报/周报筛选和版本状态。

预期：日志上下文与所选报告一致；已发布快照只读；历史列表加载不读取大体积快照字段。

### UI-008 错误与恢复

分别验证：错误类别文件、缺列 Excel、模糊图片、OCR 超时、缺基线、非周末发布周报、后端短暂不可用。

预期：

- 错误信息不包含密钥、数据库 URL、本机绝对路径或原始人员字段值。
- 错误文件不会自动落入其他空槽位。
- 失败运行提供“重试运行”；已冻结输入要求创建新运行，不允许静默覆盖。
- OCR 等待上限允许远端模型正常响应，界面保持加载状态且不重复提交。

### UI-009 响应式视觉

在 1440 x 900 和 390 x 844 下逐页检查：运行日历、运行工作台、预览、日报、周报、计算日志、系统状态、历史归档、设置。

预期：

- 页面本身无横向溢出，标题、按钮和状态徽标不被裁切。
- 宽表只在自身容器内横向滚动。
- 手机导航可打开、关闭并在跳转后自动收起。
- 日历和历史大表允许内部横向滑动；用户能看到部分下一列作为滚动提示。

### UI-010 键盘与可访问性

1. 仅用 Tab、Shift+Tab 和 Enter 遍历主导航和主要按钮。
2. 检查当前焦点有清晰外框。
3. 检查图标按钮有可访问名称，状态变化使用 `role=status` 或 `role=alert`。
4. 检查禁用的发布按钮有可理解的页面说明。

预期：焦点顺序符合页面阅读顺序；没有不可见焦点或无名称按钮。

## 6. 工作簿正确性比对

导师本机回放：

```bash
export MENTOR_DAILY_ROOT="/absolute/private/daily-root"
export APPROVED_OCR_ROOT="/absolute/private/approved-structured-images"
export REGRESSION_OUTPUT="/absolute/private/redacted-regression-output"

PYTHONPATH="$PWD" python scripts/run_single_user_regression.py \
  --mode mentor-local \
  --input-root "$MENTOR_DAILY_ROOT" \
  --start 2026-07-08 \
  --structured-image-dir "$APPROVED_OCR_ROOT" \
  --output-root "$REGRESSION_OUTPUT"
```

比对至少覆盖：

- 工作表名称、行列范围、日期列累计顺序。
- 单元格值、公式结果、样式、合并单元格和行列尺寸。
- 日报 Row2 至 Row40 和“在岗时长”。
- 周报主体/事业部、成本中心/项目和日周勾稽。
- 发布 manifest、计算日志和不可变版本元数据。

脱敏摘要只记录日期、检查维度、坐标、状态和错误代码，不回显期望值或实际值。

## 7. 本轮验收基准

2026-07-16 的隔离浏览器验收从 2026-07-07 建立完整事实基线：先通过四个正式槽位上传该日输入，再导入同日 HR 已验收日报。2026-07-06 已验收日报仅作为 W28 周报勾稽所需的前序数值基线，不替代 7 月 7 日的事实快照。

随后从 Web 页面依次完成并发布 2026-07-08、07-09、07-10、07-13、07-14、07-15、07-16 共 7 个日报运行，并在 07-10 发布 2026-07-06 至 07-10 的 W28 周报。07-11、07-12 为非工作日，按日历规则跳过。7 份日报和 1 份周报下载件与 HR 已验收工作簿在脱敏比对维度上全部一致，工作表、维度、值、样式和合并单元格差异均为 0。

本次隔离栈没有注入 Qwen 密钥。人员表和离职人员报表使用真实 Excel；OA/Release 和招聘截图使用导师已复核的结构化 Excel 转录，因此本次证明了前端四槽位、确定性计算、发布和导出链路，不作为新的远端 OCR 调用证据。2026-07-08 至 07-15 的既有验收已单独观察到 `qwen3.7-plus` 真实调用。

代码门禁结果：后端在真实日报目录和三仓上下文下 `230 passed`；前端 `29 passed` 且生产构建通过。最终浏览器会话中 API 请求全部返回 200，控制台 0 错误、0 警告。

## 8. 发布判定

以下条件全部满足才可判定前端可用：

1. 仓库自动化门禁通过。
2. 假数据浏览器全链路通过。
3. 导师本机至少覆盖连续日报和一个周报，脱敏比对通过。
4. 桌面和移动视觉检查无阻断缺陷。
5. 浏览器控制台无未处理错误。
6. 隐私扫描无真实输入、下载件、截图、密钥和业务值残留。
7. 剩余限制已记录并由验收人接受。

## 9. 测试后清理

- 删除浏览器下载的真实日报和周报。
- 删除包含真实汇总值的截图、trace 和结构化 OCR 临时文件。
- 删除临时 `.env` 和敏感值清单。
- 隔离 Docker 栈使用 `down -v` 清理；正式环境禁止带 `-v`。
- 再次运行隐私扫描并检查三个仓库的 Git 状态。
